# Androidの型番入力

2026年10月20日の利用者依頼：日本語入力中の `n78` が `ん78` になるため、Android版で英数字のまま入力できるようにする。

自動判定では、入力先頭または記号の直後にある「英字1文字＋1桁以上の数字」を英数字として扱う。数字の後ろの日本語は別の区間にする（`n78ni` → `n78に`）。英字の大小は維持する。

日本語の途中から型番を切り出さない（`nihon78` → `にほん78`、`pan78` → `ぱん78`）。明示した `nn` による「ん」、手動判定、明示的なかな表示は維持する。既存の `i18n`・`l10n`・`h2o` の判定も維持する。

検証は `android/Meltype.Android.Tests/ModelNumberTests.cs` のAndroid入力セッションで、入力中の表示と確定文字列を確認する。端末上の操作確認は別途必要。

## 英数字が交互に並ぶ型番（2026年10月22日）

`a7f1s`・`ab12cd34`のように、1〜2文字の英字と数字の組が2回以上続き、かなにならない英字を含む型番は、日本語のローマ字入力の途中でも英数字として扱う。最後の数字の後ろに、かなにならない単独の英字が続く場合は型番へ含める。後続のかなになる単位は日本語として扱う（`konoa7f1swotsukau` → `このa7f1sをつかう`、`a7f1sni` → `a7f1sに`）。かなとして読める組だけの`su1ha2`などは通常の日本語として扱う。

文中の普通の数字（`kaigiha3ji` → `かいぎは3じ`）を短い英数字の略語と誤認しない。単独の`i18n`・`l10n`・`h2o`、日本語の語尾を含む`nihon78`・`pan78`、明示的な日本語表示は維持する。判定できる型番の形を限定した規則であり、任意の型番と日本語の境界を意味から判別するものではない。

zenz版も同じ型番判定を使う。さらに、曖昧な末尾を文脈から選ぶ候補提案を追加した（ANDROID_ZENZ.md）。元表示とEnter確定は維持し、利用者が候補を選んだ場合だけ変更する。ModelBoundaryTests.csで候補選択・期限・編集後の破棄を確認する。
