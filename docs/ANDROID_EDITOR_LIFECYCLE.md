# アプリ側で入力を確定・消去した場合

未確定のまま送信すると、入力欄が空になってもIME内部の文字が残り、次の入力や確定で前の文字が戻る問題へ対応する。

OnUpdateSelectionの通知で、IMEが未確定文字を表示中なのに未確定範囲がなくなった場合は内部の変換状態を破棄する。候補、カナ表示、括弧選択、長押し操作も解除する。世代番号を更新して、破棄前の処理結果を入力欄へ適用しない。送信済みの文字を再確定・再挿入しない。

未確定範囲内のカーソル移動・文字選択では、その位置の文節を選んで候補を表示する。全文を確定せず、候補選択後も後続文節を未確定のまま残す。範囲末尾への通常の通知は文節を切り替えない。アプリ側で確定した文字は入力欄に残し、その後のIME入力は新しく開始する。未確定範囲の外への選択移動は既存どおり内部状態を破棄する。

回帰試験はEditorCompositionTestsで送信後の文字入力・確定、アプリ側の確定、通常の変換範囲と選択移動を確認する。test_external_send.pyはエミュレーター専用の独立した試験アプリを作り、実際の未確定文字、アプリ側の送信・消去・確定と次の入力を確認する。試験アプリと鍵は配布APKへ含めない。

Androidの通知仕様は[InputMethodServiceの公式資料](https://developer.android.com/reference/android/inputmethodservice/InputMethodService#onUpdateSelection(int,%20int,%20int,%20int,%20int,%20int))を参照する。

前の文節を確定して後続の文節を再表示する場合は、同じ入力操作から生じた編集結果を一度のBeginBatchEdit／EndBatchEditで反映する。確定と再表示の間に未確定範囲が消えたという通知を処理せず、後続の変換状態を保持する。入力先変更で無効化された結果は反映しない。
