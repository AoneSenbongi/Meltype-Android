# Android 0.4.0の起動失敗

2026年10月7日、公開APKを更新した後にアプリとキーボードを開けないという報告を受け、配布物を調査した。

## 確認した原因

公開0.4.0のJavaコードはMainActivityとKeyboardServiceのネイティブコールバックを呼ぶが、両ABIのlibxamarin-app.soに対応する関数がない。Javaコードは公開0.3.0と同一で、動的な登録を行う静的初期化もない。署名検証は通過し、アセンブリの識別情報とネイティブの型マップも一致する。署名・転送・Shiftの入力処理が原因であるという証拠はない。

SDK 36.1.2で同じ公開ソースを新しい作業フォルダーからビルドすると必要な関数が生成された。MainActivityへコメントだけを追加して通常の増分ビルドを行うと、警告・エラーなしでビルドが成功する一方、起動とキーボード作成の関数が再び欠落した。両ABIで再現した。原因は増分ビルド時のJavaコードとネイティブのmarshal methods生成物の不整合である。

端末のクラッシュログは未取得。端末上での例外文言とほかの不具合の有無は未確認である。この調査はAPK内部の不整合とビルドによる再現を根拠とする。

## 再現と配布前の確認

android/tools/check_apk_jni.pyはPython標準ライブラリだけで、arm64-v8aとx86_64の起動・再開・サービス起動・キーボード作成コールバックを確認する。公開0.3.0は通過し、公開0.4.0とコメント変更後の増分ビルドAPKは失敗した。

Releaseは通常の増分ビルドを配布に使わず、Rebuildで生成物を作り直す。APKを組み立てた後にcheck_apk_jni.pyを実行し、さらに配布するAPKそのものをAndroidで起動して入力を試験する。入力処理の単体試験とビルド成功だけでは公開可としない。

公開0.4.0のファイルは変更していない。再ビルドした候補の公開と既存Releaseの変更はユーザーの内容確認後に行う。
