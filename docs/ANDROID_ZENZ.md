# Androidの端末内zenz

2026-10-27、利用者の依頼により高速化試作を通常IMEへ再統合する。LocalZenz設定がオンの一般文字欄だけでモデルを準備・使用し、オフ時は従来の規則補正を維持。完全一致要求を最大64件再利用し、表記まで選択済みの誤字補正は同一文脈の後段生成へ引き継ぐ。かなだけ選んで漢字表記が未決定の場合は引き継がない。キャッシュは入力欄の切替で破棄。学習不可・機密欄では推論も個人化も行わない。通常候補、設定、更新、クリップボード、画面上の文字種切替・Shift・矢印は既存実装を保持する。入力途中の訂正表示の巻き戻り・実タッチ精度・長文上限は既知の制限として残る。統合計画と証跡はdistribution/zenz-integration-20261027/。

1.2.0の新規インストール時の端末内AIはON。保存済み設定は上書きせず、古いファイルにLocalZenzがない場合はOFFを維持する。初期値の全項目はANDROID_DEFAULT_SETTINGS_1_2_0.mdを参照。

## 実装・検証の履歴

2026-10-25の利用者指示により、当時のローカル試作の通常入力からzenzの呼び出しを停止した。モデルを使わない補正はANDROID_TOUCH_CORRECTION.mdを参照。モデルと保存設定は削除せず、10月27日に高速化した端末内AIを再統合した。以下には過去の初期値や当時の検証状況を含む。

## 対象

zenz-v3.2-small Q5_K_MをCPUで端末内実行する。モデルのSHA256は29C223D4C23327B80FD13EBB5AB2555057A46317997D5DA391584FFBEF0DB673。推論基盤はazooKey/llama.cppのb4846、commit 10131b23ee0dbd9d03dfc618cec9fe3402919277に固定する。zenzは外部APIを使わない。アプリ内更新のための通信権限は別途追加し、入力や学習データは送信しない。

この差分はPCキーボード修正と分離する。既存のMozc、辞書、設定と学習履歴を保持し、生成結果を確定済み文字列へ適用しない。端末試験は入力先とユーザーデータを保護して行う。

## ネイティブ推論

C ABIの共有ライブラリからモデルの作成、生成、中止、破棄を呼ぶ。CPUのみで動作し、文脈は512トークン、生成は最大128トークンに制限する。生成中の処理には期限と中止判定を設け、途中で打ち切った結果を成功として返さない。モデル読み込みと生成は入力画面のスレッドで行わない。

zenz-v3の入力は公式ZenzPromptBuilderに合わせ、左文脈の後に入力タグU+EE00、カタカナの読み、出力タグU+EE01を置く。左文脈は必要な範囲だけを端末内のメモリで渡す。入力・推論結果をログや共有フォルダーへ保存しない。

## セッション接続

対象は4～64文字の小文字ローマ字で、未変換の英字が表示に残り、既存RomajiTypoCorrectorが一意な修正読みを作れる入力とする。正常な英語、固有名詞、ユーザー辞書、明示的な英語・かな固定、URL等を保護する。反復誤字による自動の英語学習だけを理由に再評価を止めない。個人データの利用を禁止した入力欄では実行しない。

入力休止時間では誤字評価を始めず、ライブ変換で次の文節が現れ、後続が2文字以上の既知の読みまたは英単語として成立した時点で、直前までの区間を評価する。最後の文節は空白・句読点・確定キーで評価する（「表示どおりに確定する」がONのEnterは設定を優先する）。修正読みをMozcで変換し、元の表示、Mozc候補、修正した読みから最大5候補を作る。zenzのgrammarでその候補だけを許可し、返された文字列も候補との完全一致で検証する。候補以外の自由生成は適用しない。結果の確認は未完了の処理がある間だけ16ms間隔で行う。共通Coreの既定180msは変更せず、Androidの誤字評価は文節イベントで即座に開始する。推論の期限を短くして補正を打ち切る変更ではない。区切れた区間の評価中に後ろへ入力を続けても、未変更の訂正対象と後続入力を保持する。対象の削除・変更・取消・手動の文字種変更・入力欄変更では結果を破棄する。文節分割が誤字で崩れて対象を切り出せない場合も、空白・句読点・確定キーで入力全体を再確認する。Androidでは型番の境界を含め、zenzによる専用候補の挿入は行わない。元の打鍵は削除・取消のために保持する。モデルの選択を言語の好みとして学習しない。

Enterと通常Spaceで再評価が未完了の場合、最大1500msまで確定を保留する。失敗・期限切れは元の表示を使う。「表示どおりに確定する」が有効なEnterは待機せず表示を確定する。新しい文字入力は保留されていた確定を元の表示で先に処理し、削除・取消は保留を取り消す。非同期の結果は入力世代と照合し、編集・確定・取消・入力欄の変更後に届いた結果を破棄する。

設定の「端末内AI／zenzで文脈変換・誤字補正する」は初期OFF。モデルがないビルドでは無効にする。変換の学習がOFFでも、この設定を利用でき、推論結果や周辺文は保存しない。利用者が訂正して確定した短い誤字の組と回数は、個人誤字学習が有効な場合だけ別ファイルへ保存する。モデルの読み込み・推論は別スレッドで行い、入力処理は待機しない。評価中だけ入力側のワーカーが状態を確認する。

## 候補表示

zenzの比較用候補は推論内部でのみ使い、画面の候補一覧へ挿入しない。候補一覧の内容・順序・文節・選択位置は、元の入力に対する通常の変換結果を保持する。自動補正は未確定文字の表示とそのまま確定する文字列へ反映する。候補を選んだ箇所は利用者の選択を優先する。前方の別文節に適用済みの訂正は、後ろの候補を選んだ場合にも保持する。

従来の型番末尾の専用2択候補もAndroidでは挿入しない。型番の本体・数字を保持し、明示的な英字モードでは打ったままにする。

## ローカルビルド

次のzenz版の正式配布は、2026年10月20日の利用者指示により専用リリース鍵で署名する。鍵の管理・署名検証・既存デバッグ署名版からの移行条件は [ANDROID_RELEASE_SIGNING.md](ANDROID_RELEASE_SIGNING.md) に従う。実機診断用ビルドと正式配布物を区別する。

android/zenz-native/Build-Android.ps1へNDK、固定revisionのllama.cpp、CMake、Ninjaを指定し、arm64-v8aとx86_64をビルドする。共有ライブラリを各Native/ABI/へ置く。モデルを含む個人用候補を作るときだけ、LocalZenzModelにハッシュ確認済みGGUFの絶対パスを指定する。モデルとライセンスがAPKへ入る。通常のビルドではモデルを追加しない。公開・配布の承認は別途必要。

端末内ではモデルをアプリ専用files/zenzへコピーし、初回推論前にSHA256を再確認する。モデルの保存先と、既存Mozcの辞書・設定・学習履歴の保存先を分ける。

## 検証

ローカル候補では既存の自己診断と同様に、起動Intentのzenzselftest=trueで固定入力だけの端末内診断を実行する。実Mozc・managed adapter・同梱zenz・AndroidInputSessionの接続を検証し、結果と処理時間・プロセスメモリをfiles/zenz-selftest.jsonへ記録する。利用者の入力や学習ファイルを診断に使わない。

モデルの実体とハッシュ、ネイティブAPIのエラー処理、かな漢字生成、期限と中止、古い入力への適用防止を検証する。PCでの推論結果、Android向けビルド、Android実機での推論時間とメモリ、IMEへの適用は別々に記録する。

2026-10-20の確認結果。

- Androidセッションのテスト一式は終了コード0。新規テストで反復による自動英語学習の再評価、明示英語の保護、学習ファイル不変、候補から元の表示を選ぶ操作、削除、遅延応答、確定待ち、期限切れを確認した。
- PCの実モデルとC ABI、managed adapterを接続し、モデル準備570ms、日本語生成201ms、誤字候補の選択128msを計測した。これはPCでの一回の計測であり、Androidの性能を示さない。ネイティブsmokeのgrammar、1ms期限、不正ハンドル、容量制限も通過。
- NDK r27dでarm64-v8aとx86_64をビルド。ELFの16KB整列、依存先がAndroid標準のlibc/libm/libdlのみであることを確認。
- 共通Core.Tests全体は未通過。受け取った元ソースzipにInputSession.csがなく、既存TestSupport.cs等がそれを参照するため、CS0246でビルドできない。zenzの追加とは別の不足として記録し、既存ソースを推測で補っていない。
- 元PCでAndroidアプリをビルドし、両ABI・モデル・ライセンス・ZIP・通信権限不在・元APKとの署名一致を確認。A142へ1.1.0-zenz-rc.4を上書きし、インストールされたAPKのSHA256も配布候補と一致した。
- A142の実managed sessionでonegaishimsu、sumimasne、arigatpuの補正が通過（確定待ち218〜304ms、初回準備487ms、単発）。github/cameraは不変。管理画面でLocalZenzをON、EnterCommitsAsShownをOFFにし、実際のIMEでも「お願いします」「ありがとう」の補正、githubの維持、確定、確定後削除を確認した。
- 更新前のAPKとアプリデータを退避。最終照合で既存13ファイル中12点はバイト一致し、設定ファイルはLocalZenzの追加とEnterCommitsAsShownの変更だけ。辞書・学習データは保持した。長期精度や多様なアプリ・誤字は未検証。公開はしていない。

残る確認事項として、候補を作るMozc呼び出しは入力ワーカー上で動き、既存のMozc側の上限に依存する。1500msは非同期評価器を待つ期限であり、候補生成時間を含む厳密な全体上限ではない。実機で候補生成の遅延を測定し、入力を妨げる場合は候補生成も別ワーカーへ移すこと。初回のモデル準備は入力欄開始時に非同期で先行させる。

## 1.1.0をビルドする

通常のAPKビルドに、`-p:LocalZenzModel=<zenz-v3.2-small-Q5_K_M.ggufの絶対パス>`を加える。モデルの入手先、revision、SHA-256、ライセンスはandroid/zenz-native/licenses/ZENZ-NOTICE.txtに固定している。llama.cppを同ファイルのcommitへ合わせ、Build-Android.ps1にNDKとそのソースパスを渡し、両ABIのruntimeを生成してNative/ABIへ配置する。Mozcと.NETのビルド手順はANDROID_PROTOTYPE.mdと既存のワークフローを参照する。

Assets/THIRD_PARTY_NOTICES.txtを既存の通知収集手順で作り、android/zenz-native/licensesの3ファイルの内容も追加する。公開APKでは、この通知に加えて各ライセンスをAPK内assets/licenses/zenzへ含める。秘密鍵・個人の辞書・学習データ・端末バックアップをビルドやソースZIPへ含めない。

個人の誤字学習（ローカル修正）：zenzと変換の学習がONの場合、未確定の短いローマ字を訂正して確定すると、zenzが訂正を確認します。手動訂正を1回承認すると、次回から文脈を確認して自動補正します。訂正からキーの押し間違い・脱字・重複・順序逆転を学び、別の語にも応用します。端末内に短い訂正前後と回数だけを保存します。モデルの重みは変更せず、周辺文は保存・送信しません。詳細はdocs/ANDROID_PERSONAL_TYPO_LEARNING.md。


2026年10月24日、A142の学習用code19で、入力休止待機40ms・結果確認16msを含む固定入力3例のライブ誤字表示を302/250/264msと計測した。同じ文脈あり型番判定3例はcode18の445/418/448msから275/265/269msへ短縮し、固定診断18件が通過した。短い誤字の確定待ちは232/198/194ms、初回モデル準備は479ms。これらは固定入力の単回測定で、すべての入力や初回起動の0.3秒上限を保証するものではない。実機へ適用し、診断ファイルの復元後も元18ファイルのハッシュと既定IMEを確認した。

文節イベント方式の試作では、従来の誤字候補生成と同様、1回の未確定入力内の補正は1か所を対象にする。受理済みの訂正対象は後続入力によって再推論せず保持する。複数箇所を連鎖して直す処理は追加していない。自動文節の境界が判別できない語は空白・句読点・確定時に扱う。


Androidのzenz誤字補正は、未確定文字の表示とそのまま確定する文字列にだけ適用する。候補は元の入力を通常の変換エンジンへ渡した一覧・順序・選択位置・文節分割を保持し、zenzの比較用候補で差し替えない。候補を明示的に選んだ箇所では利用者の選択を優先する。訂正対象より後ろの文節を選んだ場合は、前方の表示済み訂正と選択した後続候補を確定する。Androidの型番境界の専用2択候補も生成・挿入しない。元の型番保護と通常候補の操作は保持する。他プラットフォームの既定の動作は変更しない。


## 文節イベントとニューラルかな漢字変換の併用（ローカル試作）

文節が区切れたとき、誤字がない既知の日本語の読みもzenzのかな漢字変換へ渡す。個人の訂正傾向や既存の誤字規則が修正案を作った場合は、まず従来の比較で元の表示と修正案を判定し、採用された読みをニューラル変換へ渡す。拒否された修正案は次の生成へ進めない。かな漢字変換の生成自体は比較用の少数候補に限定しないが、生成結果をMozcの文節ごとの通常候補につなげて当てはめられる場合だけ表示へ使う。当てはまらない・英数字や記号を変更する・失敗する場合は通常変換（誤字承認後はその承認済み表示）を保持する。画面の通常候補・並び・文節・手動選択は変更しない。

誤字比較と生成の非同期待機は同じ開始時点から合計1500msを上限とし、後段で期限をリセットしない。誤字なしは生成1回、誤字ありは比較と生成で最大2回の推論となる。旧版の固定入力での0.3秒前後という実測を、この版の性能として扱わない。実機は取り外しの指示が継続しているため操作しない。固定入力のエミュレーター診断とローカル検査を行い、実機確認は再接続後に分ける。
