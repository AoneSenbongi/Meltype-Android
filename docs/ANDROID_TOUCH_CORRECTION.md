# タッチ根拠と誤字補正の統合

2026-10-25。利用者の「一旦、zenz無しで実装」により、現在の試作は座標・既存規則・Mozcだけで動かす。通常入力からzenzを生成・準備・呼び出しせず、保存済みLocalZenzがONでも使用しない。設定一覧から一時的にzenzスイッチを外すが、保存値や既存モデル・学習ファイルは削除しない。

誤字の候補提示を増やさず、意図しない変更を増やさない範囲で訂正操作を減らす。

## 処理順

1. 文字キーは元のキーのまま入力する。押下時の実キー矩形から、同じ行の境界付近だけ近隣キーの代替案を保持する。中央、空白、操作キーは対象外。座標・代替案は未確定入力中のメモリだけに置く。
2. 文節・句読点・確定の既存イベントで、通常の誤字規則とタッチ根拠の案を重複排除する。候補が複数残る場合は自動補正しない。規則だけの補正は既存Fixの既知語・編集コスト・順位差の条件も満たす必要がある。
3. 一意に決まった読みだけを通常のMozc変換へ渡す。周辺文による別表現の生成、同音異義語のモデル再評価、推論待ちやポーリングは行わない。既存の静的な個人ローマ字補正は元の条件を維持し、zenzによる訂正学習は使わない。
4. 補正は未確定表示とそのまま確定する文字にだけ反映する。通常候補の内容・順序・文節・選択位置を変えない。利用者の明示選択を優先する。

語の途中でタッチ補正を適用した後も、句読点や確定時に語全体のタッチ案が一意に決まる場合は全体の読みを再評価する。途中の文節変換を固定したまま語末を別に変換する状態を残さない。元の読みが既知の場合の保護と、複数案がある場合の原文保持は同じ条件を使う。

「表示どおりに確定する」がONの場合、Enterでは新しい補正を追加せず表示をそのまま確定する。確定時に新たな補正を評価するのはSpace、または同設定がOFFのEnter。文節・句読点で既に表示へ反映した補正は保持する。

## 保護と競合回避

- 明示英語、既知の英単語、型番、数字、ユーザー辞書、機密欄の既存保護を維持する。
- 候補がない、複数ある、変換に失敗した場合は元入力を保持する。従来の次文字予測による押下先の即時置換は、この統合経路へ置き換える。
- 中央を押した文字はタッチ補正案を作らない。近隣キーの判定は実レイアウトを使い、画面サイズや片手モードの固定座標に依存しない。
- 元の読みが既知の日本語として区切れる場合は、タッチだけでは別の読みへ変更しない。既存の静的な個人ローマ字補正と個人辞書は従来の処理に委ね、タッチで重ねて変更しない。zenzで承認した訂正の再評価・学習は停止する。
- 削除、カーソル移動、明示候補選択、モード変更、リセットでは座標根拠を破棄する。確定後の別入力へ持ち越さない。
- 座標由来の案や自動補正の結果を新たな誤字学習へ保存しない。通常の変換学習の設定とデータは維持する。削除を誤補正の拒否だと推測して学習する処理は追加しない。

## 長文入力の重複処理削減（2026年10月26日）

AndroidのMozc呼び出しは、同じ読み・前文脈・実効学習モード・通常変換/全文節候補取得の組について、成功した文節と候補を最大32組メモリ内で再利用する。通常変換と手動で文節を結合した候補取得を区別する。別の読みの候補取得後にも、再利用する結果の候補一式を復元する。呼び出し側による候補・文節配列の変更を保存結果へ持ち込まない。実効学習モードが変わった場合と、学習処理を開始した場合は破棄する。失敗や読み不一致は保存しない。既存の変換条件・候補順・文節境界は変更しない。

タッチの代替案が空の場合は、既知読みの照合をせず空結果を返す。座標がある場合の既知読み保護は維持する。速度の改善は固定の語彙評価・長文実機評価で確認する。

## 検証

再現試験を実装前に追加する。境界と中央、複数案、読める誤字、拒否・失敗、候補保持、削除・リセット、明示英語、学習OFFを確認する。既存Android回帰、ソース検査、Android APKビルドを実行し、実機の有効性・精度評価はローカル検査と区別する。

## zenzの位置付け

通常入力経路では使用しない。既存モデル、診断用コード、他プラットフォームのモデル機能は削除しない。将来再検討する場合も、zenz有無での誤補正率、訂正操作数、通常時・初回・長文の遅延を比較するまでは、必要性や改善を主張しない。
